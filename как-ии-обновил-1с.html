Автообновление типовой на поддержке

Контур агента Cursor: не MCP:RSV Data и не OData. Штатная цепочка поставщика: CFU → DESIGNER /UpdateCfg + /UpdateDBCfg → ENTERPRISE обработчики ИБ. Оркестратор — update_1c_universal.ps1 на 192.168.80.15, ИБ на кластере servsql.

Граница ответственности

Агент не делает

Не правит cf/cfe в EDT. Не ходит в ИБ через HTTP MCP. Не жмёт UI легальности (UIPI/SYSTEM ломает чекбокс). Не гоняет параллельные 1cv8 по одной базе.

Агент делает

Собирает cmdline DESIGNER/ENTERPRISE, COM к ИБ, COM к кластеру (регзадания), ждёт cond-функции БСП, режет только процессы этой ИБ (Srvr+Ref, в т.ч. /S"servsql/ref").

Поток на один прогон

1

Вход

Srvr, Ref, пользователь 1С. Платформа 8.3.27.2214.

2

Идентификация

V83.COMConnector → Метаданные.Имя / Версия. DumpConfigToFiles не используем (зависает).

3

Цепочка CFU

От текущей до последнего в каталоге по 1cv8upd.htm (from-versions). Не «любой cfu из папки».

4

Цикл шагов

На каждый CFU: DESIGNER, затем ENTERPRISE. См. ниже.

5

Контроль

Снова COM: финальная Версия. Закрыть 1cv8 только этой ИБ.

Один шаг CFU (ядро)

ScheduledJobsDenied = True          // иначе ФЗ держат исключительную блокировку
DESIGNER /S Srvr\Ref /N /P
  /UpdateCfg "<file.cfu>"
  /UpdateDBCfg -Server
  // ArgumentList через ProcessStartInfo.Arguments — иначе /UpdateCfg теряется
ScheduledJobsDenied = False         // иначе отложенные обработчики не стартуют
COM: ЗаписатьПодтверждениеЛегальностиПолученияОбновлений
ENTERPRISE /C ЗапуститьОбновлениеИнформационнойБазы
wait COM:
  НЕ НеобходимоОбновлениеИнформационнойБазы()
  И ОтложенноеОбновлениеЗавершено()
Stop-ThisIB                         // cmdline содержит и Srvr, и Ref

Легальность UI ненадёжна (сессия под SYSTEM / PsExec -s -i 2). Отложенное обновление нельзя считать успешным по idle процесса: окно «Обновление версии приложения» ещё крутится.

Почему цепочка, а не один CFU

Файл обновления принимает только перечисленные в нём from-версии. Пример БП 14.09.2026, agashin_zup_copy (в Ref лежала БП после смены конфигурации): прямой 195.40→205.17 даёт «файл не содержит доступных обновлений». Факт:

Где это лежит

Скрипт: update_1c_universal.ps1 → \\192.168.80.15\C$\temp\. Запуск на сервере (PsExec). Один сеанс 1cv8 на ИБ. Timeout шага до 6 ч. Бэкап по умолчанию, -SkipBackup на копиях.

MCP (user-rsv-data / depo_copy2) — другой контур: чтение метаданных и запросов, модули в ИБ не пишет. Путать с обновлением CFU нельзя.
