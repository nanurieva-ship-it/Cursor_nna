# Счёт: проверка лимитов и создание заявки

Образец HTTP-сервиса 1С: как **вернуть в ответе не только код 200/500, но JSON с лимитами** (статья, сумма, остаток).

Проблема в исходном коде: `HTTPСоединение.ОтправитьДляОбработки()` даёт объект `HTTPОтвет`. Код состояния — это только `Результат.КодСостояния`. Тело ответа (статья + сумма) читается отдельно: `Результат.ПолучитьТелоКакСтроку()`. На стороне БП тело нужно явно записать в `HTTPСервисОтвет`.

## Что сделать в конфигураторе БП

1. HTTP-сервис `ImportFromDO` (как сейчас).
2. **Два шаблона URL**, не один `Download` на всё:
   - `CheckLimits` — POST, проверка графика платежей по статьям.
   - `Download` — POST, создание заявки.
3. У обоих шаблонов метод POST, обработчик в модуле сервиса.

Корневой URL сервиса тот же, меняется только хвост:

```
/sah_buh_akea/hs/ImportFromDO/CheckLimits
/sah_buh_akea/hs/ImportFromDO/Download
```

## Контракт ответа проверки лимитов

Всегда HTTP **200** и JSON в теле: и лимит, и создание заявки, и ошибка разбора (`success=false`). **500 не отдаём** — ДО читает тело, а 500 часто приходит пустым. Превышение лимита — бизнес-результат, не ошибка транспорта. Остаток по статье в `message` всегда.

```json
{
  "success": true,
  "overLimit": false,
  "message": "",
  "limits": [
    {
      "articleCode": "00-000012",
      "articleName": "Оплата товара",
      "limitAmount": 100000.00,
      "spentAmount": 40000.00,
      "requestAmount": 25000.00,
      "remainder": 60000.00,
      "overLimit": false
    }
  ]
}
```

При превышении: `"overLimit": true` и тот же массив `limits` — ДО покажет пользователю статью и сумму.

## Как прочитать ответ в ДО

```bsl
Результат = HTTPСоединение.ОтправитьДляОбработки(ЗапросPOST);
ТелоОтвета = Результат.ПолучитьТелоКакСтроку("UTF-8");

Если Результат.КодСостояния <> 200 Тогда
    ВызватьИсключение СтрШаблон("БП вернула %1: %2", Результат.КодСостояния, ТелоОтвета);
КонецЕсли;

ЧтениеJSON = Новый ЧтениеJSON;
ЧтениеJSON.УстановитьСтроку(ТелоОтвета);
Данные = ПрочитатьJSON(ЧтениеJSON); // структура: success, overLimit, limits
```

`ПрочитатьJSON` превращает JSON-объект в `Структура`, массив — в `Массив` структур. Имена ключей как в JSON (`articleCode`, не `СтатьяКод`), если не задавать соответствие имён.

## Почему не работали исправленные процедуры

ДО собирало JSON так:

```json
[{"Стр1": {"ДатаПлатежа": "23.09.2026", "Сумма": 15000, "СтатьяДДС": "Оплата товара"}}]
```

БП читало `ТекСчет.статьяДДС`, `ТекСчет.Сумма`, `ТекСчет.ДатаПлатежа` у **корня** элемента. Этих свойств нет (они внутри `Стр1`). Плюс в корень клали код статьи, а в график — **наименование**; верхнюю структуру в массив не добавляли. Дата уходила строкой `ДЛФ=Д`, а `ПроверкаЛимитов` ждёт тип `Дата` → исключение и 500 без тела.

Нужен плоский массив строк проверки. Готовые модули: `CheckLimitsDO/Module.bsl` и `ПроверитьЛимитВДО.bsl`.

## Типичные ошибки

1. **Не вызывали `УстановитьТелоИзСтроки`** у `HTTPСервисОтвет` — клиент видит 200 и пустое тело.
2. **`Сообщить()` в HTTP-сервисе** не уходит в HTTP-ответ. Только тело `HTTPСервисОтвет`.
3. **`ВызватьИсключение`** без `Попытки` → платформа отдаёт 500 без вашего JSON.
4. В `ПроверитьЛимитВДО` не создавался `Массив` и не передавались статья ДДС / сумма — в БП нечего считать.
5. Проверка и создание заявки шли на один URL `Download`. Разведите методы: сначала CheckLimits, при `overLimit = Ложь` — Download.

## Регистрация счёта → «На согласовании»

Файл: `do/Forms/ВнутреннийДокумент/РегистрацияИОтправкаВБП.bsl`.

В расширении уже есть `&После("Зарегистрировать")`: выгрузка в БП и `ОтправитьОбъекты.Доступность = Ложь`.

После этого вызывается `УстановитьСостояниеНаСогласовании()` — штатный `ИзменитьСостояние` формы с `Перечисления.СостоянияДокументов.НаСогласовании`. Обновляются `СостояниеТекст` и доступность полей.

## Согласование БП → ДО (`FromBuhStatus`)

Почему статус не садился в график ДО:

1. **Искали `НайтиПоКоду(КодСчета)`**, а из БП уходит `НомерСчетаДО` — это регистрационный номер, не `Код` справочника. Документ не находился → 500.
2. **Дата `ДЛФ=Д`** (`25.09.2026` или `25 сентября 2026 г.`). `СтрокаВДату` часто даёт пустую дату, сравнение с `текграфик.ДатаПлатежа` не срабатывает.
3. **Документ найден, дата не совпала** — функция **не возвращала** `HTTPСервисОтвет`. Платформа отдаёт ошибку, в БП только «Не удалось отправить».
4. Права пользователя HTTP-сервиса: запись счёта без привилегированного режима падает в `Исключение` → 500 без текста.

Контракт (как в `examples/status-request.json`):

```json
[{"Статус": true, "ДатаПлатежа": "20260925", "КодСчета": "СЧ-000123"}]
```

Ответ ДО всегда HTTP 200 + JSON: `success`, `message`.

Журнал регистрации (без отладчика):

- БП — событие **ОтправкаСтатусаВДО**: старт с типом статуса/даты/номера, JSON, URL, код HTTP, тело ответа, success/message.
- ДО — событие **FromBuhStatus**: вход в сервис, сырое тело, ключи JSON, поиск по коду и по рег. номеру, каждая строка графика (даты и совпадение), запись объекта, исходящий JSON.

Если в БП есть вызов, а в ДО тишина — не тот URL/метод или публикация HTTP-сервиса. Если в ДО «счёт не найден» — в БП смотрите `НомерСчетаДО`.

Состояние документа по графику:

- все строки `Согласовано = Истина` → `Согласован`;
- хотя бы одну сняли → сбрасываем `Согласован` обратно на `На согласовании`.

Пустой график не трогаем. Если состояние уже нужное — повторно не пишем. В журнале: «согласовано N из M», текущее и целевое состояние.

Файлы: `do/HTTPServices/FromBuhStatus/Module.bsl`, `bp/Forms/Заявка/ОтправкаСтатусаВДО.bsl`.
