# Расширение формы внутреннего документа (ФУ)

Модуль: `do/FormExtension.bsl`. Копия того же текста: `do/Forms/ВнутреннийДокумент/РасширениеФормы.bsl`.

Расширение трогает только два вида внутренних документов:

- «Счёт на оплату» — `a963c455-a1c9-11eb-b511-a7abe965c408`
- «Плановая заявка» — `75844040-bd80-11f1-a615-9c69b465b0dd`

Остальные виды не меняются: своя кнопка для них скрыта. Типовую команду `Зарегистрировать` расширение не переименовывает и не подменяет.

Статусы из БП сюда не входят. Их принимает HTTP-сервис `ФУ_ЗагрузкаСтатусовИзБух`, модуль `do/FromBuhStatus.bsl`.

## Что делает форма

Служебные реквизиты `ак_ИдётРегистрация`, `ак_НазначениеПлатежа`, `ак_ОтправленоВБП` добавляются один раз в `&После("ПриСозданииНаСервере")`. Повторный `ИзменитьРеквизиты` даёт «Имя не уникально», поэтому `&После("ПриИзмененииВидаДокумента")` реквизиты не создаёт: типовой `ПриСозданииНаСервере` вызывает смену вида раньше, чем `&После("ПриСозданииНаСервере")`.

Своя команда одна: `ак_ОтправитьНаСогласование` («Отправить на согласование»), кнопка `ак_КнопкаСогласование` в `ГруппаОсновнаяКомПанель`. Типовые команды формы (`СкопироватьСвязанныеФайлы`, `СоздатьПлатежку`, `ОтправитьРаспознать` и остальные) расширение не добавляет.

У серверной процедуры и функции директива `&НаСервере` или `&НаКлиентеНаСервереБезКонтекста` стоит сразу над объявлением.

## Запись

`&Вместо("ПередЗаписью")` сначала выполняет свои проверки, затем `ПродолжитьВызов`.

- Плановая заявка без `СрокИсполнения` не пишется. Срок уходит в БП как запланированная дата графика. Получатель для плановой не обязателен.
- Счёт, созданный по плановой, пишется только если плановая в состоянии «Согласован». Открытие такого счёта при создании тоже отклоняется.
- Перед записью обоих видов один запрос `ПроверитьЛимитДокументаВДО` — POST JSON на `CheckLimitsDO/Ch`. Остаток всегда показывается предупреждением. Остаток 0 и меньше — лимита нет.
- Плановая после предупреждения записывается. Счёт без лимита записывается только при `СверхЛимит = Истина`.

`&Перед("ПриЗаписиНаСервере")` для плановой ещё раз требует срок и записывает назначение в объект. Обработчика `&После("ПриЗаписиНаСервере")` нет: связи договора и старые виды (договор покупки, заявка на оплату) расширение не ведёт.

## Отправка в БП

Кнопка `ак_ОтправитьНаСогласование` один раз вызывает `ОтправитьНаСогласованиеВБП` — POST JSON на `ImportFromDO/Download`. Повторная отправка в том же сеансе блокируется реквизитом `ак_ОтправленоВБП`.

Успех — HTTP 200 и `success` в JSON (либо тело `OK`). Если БП ответила автосогласованием, состояние документа в ДО становится «Согласован», иначе «На согласовании».

В JSON уходят вид, идентификатор ДО, сумма, статья ДДС, срок, назначение, контрагент, график платежей и файлы документа. Для счёта без своих файлов берутся файлы плановой-основания.

Назначение плановой — реквизит формы `ак_НазначениеПлатежа` и типовое поле, если оно есть. При создании счёта по плановой назначение копируется с основания.

## Подключение к БП

Копия ДО (`doc_sah`) ходит на `1c.akea-ds.ru:59795`, путь `/buh_sah_copy/hs/`. Рабочая ДО (`doc_akea`) — на `1c.sah18.ru:59795`, путь `/bb8df6a3-e002-4456-bd58-897119e54052/hs/`. Пользователь, порт и пароль заданы в `ПараметрыПодключенияКБП`, соединение по TLS OpenSSL.
