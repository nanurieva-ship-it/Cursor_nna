# Плановые заявки ДО ↔ БП

Счёт ↔ заявка на оплату уже работает. Этот контур — **плановые заявки** (в ТЗ: ЗРДС).

## Название

| Где | Как называть | Почему |
|-----|----------------|--------|
| ДО, вид внутреннего документа | **Плановая заявка** | Коротко, понятно канцелярии. Не «ЗРДС». |
| ДО, полное имя вида | Плановая заявка на оплату | Если в списке видов нужно отличить от счёта |
| БП | Тот же документ заявки на оплату, флаг **`ПлановаяЗаявка`** | Не плодим второй объект. Обычная заявка из счёта: флаг `Ложь`. Из плановой заявки ДО: `Истина`. |

В коде и JSON поле `ВидДокумента` = `"ПлановаяЗаявка"`.

Не использовать в интерфейсе ДО: ЗРДС, ЗНО, ФП — это жаргон БП.

## Что уже есть (счёт)

- Проверка лимита графика: `CheckLimitsDO`
- Выгрузка счёта → заявка в БП: `ImportFromDO/Download`
- Согласование строки графика БП → ДО: `FromBuhStatus`
- Регистрация счёта → состояние «На согласовании»

## Очередь по вашим пометкам

1. **Сейчас (первый приоритет, расширение САХ):** плановая заявка + статьи ДДС.
2. Счёт: назначение платежа, сверхлимит, лимит при записи, регистрация как сейчас.
3. Правило 5% и статусы плановой в БП — Савелий в БП.
4. Контрагенты ДО → БП — не в контуре ФУ, согласовать с Максимом.
5. Договоры — в ДО строка, справочник не ведём, пока не делаем.
6. Автовозврат резерва через N дней — **не делаем**. Козлов возвращает вручную.

Проверки лимита оставляем **синхронными по HTTP** (как счёт): иначе пользователь не видит «остаток N» в момент записи. Если БП недоступна — отказ с текстом в журнале, документ не «тихо» уходит.

## Этап 1. НСИ

### Статьи ДДС: БП → ДО (мастер — БП)

При записи статьи в БП — POST в ДО. Поиск в ДО по `Код` (и `ИдентификаторБП`, если заведён).

Роль на создание/изменение в БП: **Полный доступ ФУ** (финдир). Остальным — просмотр. HTTP-сервис пишет в привилегированном режиме.

### Контрагенты: ДО → БП (мастер — ДО)

Заготовка готова, **не включаем в прод**, пока не скажет Максим. Синхронизация по ИНН (+КПП). Создание вручную в БП — только бухгалтер; обмен идёт от имени сервиса.

### Договоры

Не делаем.

## Этап 2. Плановая заявка

Реквизиты вида в ДО (доп. реквизиты / ТЧ свойств — как удобнее в расширении):

| Реквизит | Тип |
|----------|-----|
| Дата | Дата |
| Организация | Справочник.Организации |
| Статья ДДС | ссылка, код из БП |
| Сумма | Число 15.2 |
| СверхЛимит | Булево |
| НазначениеПлатежа | Строка |
| ИдентификаторДО | UUID ссылки |

Поток:

1. Запись / «Отправить»: POST лимита в БП (`СтатьяДДС` + `Сумма` + период).
2. Ответ всегда текст + JSON: «Лимит одобрен. Остаток: N руб.» или «Лимит превышен. Недостает: N руб.»
3. Если лимита нет и не сверхлимит — не выгружаем, статус не «Отправлен».
4. Если ок или сверхлимит — POST создания заявки в БП, `ПлановаяЗаявка = Истина`.
5. В ДО состояние **Отправлен**.
6. Финдир в БП **одобрил** → расход регистра Бюджет ДДС видом **План** (Савелий) → статус в ДО **Одобрен** → подзадача «Создать счёт на оплату» со ссылкой на плановую заявку.
7. **Отклонил** → сторно движений (Савелий) → в ДО **Отклонен**. Резерв вручную, без автомата «через 3 дня».

## Этапы 3–5 (счёт и обычная заявка)

Уже в работе. Добавить в выгрузку счёта: `НазначениеПлатежа`, `СверхЛимит`, `ИдентификаторСтрокиГрафика`.

Правило 5%: если заявка в БП создана не как плановая, а **по счёту**, который ссылается на одобренную плановую — `СуммаСчета <= СуммаПлановой * 1.05` → сразу «Одобрен», иначе «На согласовании».

Идентификатор строки графика — чтобы правка даты в ДО обновляла строку ЗНО, а не плодила дубль.

Оплата ПП → счёт в ДО «Исполнен» — отдельный сигнал, не путать с согласованием строки.

## Журнал

| Событие | База |
|---------|------|
| `СтатьиДДС_БП_ДО` | БП, при записи статьи |
| `ImportNSIDO` | ДО, приём статьи |
| `Контрагенты_ДО_БП` | ДО, при записи (когда включат) |
| `ImportNSIBP` | БП, приём контрагента |
| `ПлановаяЗаявкаДО` | ДО, лимит и выгрузка |
| `ImportFromDO` | БП, создание заявки |
| `FromBuhStatus` | ДО, статусы из БП |
| `ОтправкаСтатусаВДО` | БП, статусы в ДО |

Булевы в конкатенации журнала всегда в скобках: `+ " пустое=" + (Не ЗначениеЗаполнено(Тело))`.
