Помощь с кодом 1С: MCP, не OData

Если база подключена через MCP:RSV Data — это лучший канал, чтобы писать модули под вашу конфигурацию, а не «типовой БП из учебника».

MCPчтение метаданных и данных
.bslкод — файл на диск
ODataдля Excel и обменов

Зачем MCP для кода

Агент видит живую базу: имена объектов, реквизиты, табличные части, синонимы и примеры строк. Процедуры получаются под ваши объекты.

Пример. Документ.ФУ_ЗаявкаНаОплату, ТЧ ГрафикПлатежей — ДатаПлатежа, СуммаКОплате, Статус. Не абстрактная заявка из учебника, а то, что в ДЕПО.

Что агент берёт из MCP

ИнструментЗачем для кода
configКонфигурация, версия, расширения
describe / get_structureОбъекты, ТЧ, типы, перечисления
query / execute_queryЖивые строки, язык запросов 1С
revealРасшифровка ФИО человеку

Чего MCP не делает

Читает

Метаданные, справочники, документы, регистры, остатки.

Не пишет в 1С

Не вставляет модуль в конфигуратор, не проводит документ, не проверяет компиляцию в дизайнере.

Результат — текст .bsl. Его копируете в объект вы.

Если MCP к базе нет

Код всё равно можно писать по выгрузке конфигурации, скринам формы или описанию. Просто больше угадывания имён.

Правило. База подключена через MCP — пишем код через него. Нужна выгрузка в Excel или обмен — OData. Нет ни того ни другого — файлы и скрины.

Стрелки ← → или кнопки. Файл можно открыть в браузере на весь экран (F11).
